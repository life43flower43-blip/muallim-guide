# النسخ الاحتياطي والاستعادة

## ثلاث طبقات حماية

| الطبقة | ماذا تحفظ | أين | متى | المدة |
|---|---|---|---|---|
| 1. GitHub | الكود، والمقالات، والمفاهيم، والأسئلة، والصور | مستودع GitHub (مستقل عن Vercel) | مع كل تعديل | كل التاريخ |
| 2. نسخة قاعدة البيانات | الحسابات، والتقدم، والأخطاء، والنقاط، والاشتراكات | GitHub Actions Artifacts، مشفرة AES-256 | كل ليلة 3 فجرًا بتوقيت مكة | 30 يومًا |
| 3. نسخة الطوارئ الخارجية | نسخة قاعدة البيانات المشفرة يوميًا، ونسخة المستودع كاملًا أسبوعيًا | تخزين S3 متوافق خارج GitHub وVercel وNeon (مثل Cloudflare R2) | يوميًا وأسبوعيًا | حسب قاعدة الحذف في الحاوية (يُنصح 90 يومًا) |

الملف: `.github/workflows/db-backup.yml`. ويمكن تشغيله يدويًا في أي وقت من تبويب Actions، ثم «نسخ احتياطي لقاعدة البيانات»، ثم Run workflow.

## اختبار الاستعادة تلقائيًا كل مرة

كل نسخة تُستعاد فعليًا في قاعدة PostgreSQL مؤقتة داخل GitHub Actions، ويُعد كل جدول في الأصل وفي النسخة المستعادة. إن اختلف أي رقم، تفشل المهمة ويظهر تنبيه أحمر. وملخص كل تشغيل يعرض: التاريخ، وعدد سجلات كل جدول، وبصمة الملف (SHA-256)، وهل حُفظت النسخة الخارجية.

## إصدار PostgreSQL

تقرأ المهمة إصدار قاعدة الإنتاج في كل تشغيل (Neon يعمل حاليًا بالإصدار 18)، وتثبّت أداة النسخ وقاعدة الاختبار بالإصدار نفسه، فلا تتعطل إن حدّث Neon الإصدار.

## الإعداد (مرة واحدة)

في GitHub: Settings > Secrets and variables > Actions > New repository secret:

- `DATABASE_URL`: رابط قاعدة الإنتاج من Vercel (Settings > Environment Variables) أو من Neon.
- `BACKUP_PASSPHRASE`: كلمة سر طويلة لتشفير النسخ. احفظها خارج الحاسوب أيضًا (ورقة في مكان آمن). **بدونها لا يمكن فتح أي نسخة.**

للطبقة الثالثة (اختياري لكن موصى به)، أنشئ حاوية في Cloudflare R2 (مجانية حتى 10GB) أو Backblaze B2، ثم أضف:

- `BACKUP_S3_ENDPOINT`: مثل `https://<account-id>.r2.cloudflarestorage.com`
- `BACKUP_S3_BUCKET`: اسم الحاوية
- `BACKUP_S3_ACCESS_KEY` و`BACKUP_S3_SECRET_KEY`: مفتاحا API بصلاحية الكتابة على هذه الحاوية فقط

وفعّل في الحاوية قاعدة حذف تلقائي للملفات الأقدم من 90 يومًا.

## الاستعادة عند الطوارئ

1. نزّل أحدث نسخة: من Actions > آخر تشغيل ناجح > Artifacts، أو من الحاوية الخارجية (`db/db-<التاريخ>.dump.gpg`).
2. تحقق من البصمة: `sha256sum -c db-<التاريخ>.sha256`
3. فك التشفير:
   ```
   gpg --decrypt db-<التاريخ>.dump.gpg > db.dump
   ```
4. أنشئ قاعدة جديدة فارغة (في Neon: فرع أو قاعدة جديدة)، ثم استعد إليها:
   ```
   pg_restore --no-owner --no-privileges --exit-on-error --dbname="<رابط القاعدة الجديدة>" db.dump
   ```
5. قارن عدد السجلات بملف `db-<التاريخ>.counts.txt`.
6. ضع رابط القاعدة الجديدة في `DATABASE_URL` في Vercel، ثم Redeploy.

لا تستعد فوق القاعدة الحالية مباشرة. استعد في قاعدة جديدة، وتأكد منها، ثم بدّل الرابط.

## الكود والمحتوى

أي نسخة سابقة من الموقع: Vercel > Deployments > اختر نشرًا قديمًا > Promote to Production. أو من نسخة المستودع الخارجية: `git clone repo-<التاريخ>.bundle`.

## ما جُرّب قبل التسليم

جُربت خطوات المهمة نفسها على قاعدة PostgreSQL محلية ببنية الجداول الحقيقية (7 جداول) و1700 سجل تجريبي: النسخ، والاستعادة، ومطابقة العدد في كل جدول، والتشفير، ثم فك التشفير والاستعادة في قاعدة ثالثة، واسترجاع مستخدم بعينه وتقدمه. ورُفضت كلمة سر خاطئة. لم تُجرّب بعد على قاعدة الإنتاج، فذلك يحدث في أول تشغيل بعد إضافة الأسرار.
